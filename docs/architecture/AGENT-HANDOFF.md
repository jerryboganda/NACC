## 1. Non-negotiable product and execution rules

- Windows-first Tauri 2 desktop app; privileged behavior stays in Rust.
- React + TypeScript + Vite is the webview UI; there is no runtime Node/Python/Go/.NET application server.
- The webview never receives a general shell or unrestricted filesystem capability.
- SQLite uses embedded Rust migrations.
- Process trees are contained on Windows and cancellation must not orphan descendants.
- Write-enabled parallel workers use isolated Git worktrees; the primary checkout must not be silently mutated.
- Provider-native OAuth/token contents are never copied, read, logged, or stored by NACC. GitHub integration uses the authenticated `gh` CLI.
- Unsupported or unverified provider/model functionality is typed-blocked or shown unavailable. Never invent capabilities or model catalogs.
- Production deploys, releases, signing, destructive operations, repository visibility changes, and workflow dispatch/reruns require explicit human authorization.
- Heavy builds, full tests, matrices, packaging, security scans, and other CPU-intensive verification belong in GitHub Actions whenever technically feasible. Do not use the production VPS as a build/test machine.
- Preserve unrelated user work. In particular, `.zcode/` is user-owned and must remain untouched.

## 5. Optional product backlog and hardening gaps

The following are not complete and must remain explicit, but they do **not**
block the current personal local-only readiness target:

1. **Workflow Designer mutation/edit UI** — the mounted Workflow Inspector is read-only. Built-ins must remain read-only; custom template create/edit/delete requires a complete validated mutation contract and explicit destructive confirmation.
2. **Worktree mutation/destructive controls** — the mounted Worktree Manager is read-only. Do not add cleanup/delete/release controls without a separate privileged safety/authorization design.
3. **Quality/Review lifecycle completion** — workflow nodes have a backward-compatible, machine-readable `quality_gates` declaration (`name`, exact `argv`, timeout, required/optional), graph validation, deterministic contained execution after provider success, durable per-attempt evidence, and required-gate blocking/retry enforcement. Read-only IPC and the mounted Quality & Review Center also exist. Still missing are automatic review-finding lifecycle integration, disposition/waiver/repair-request lifecycle, richer execution metadata, and explicit rerun policy.
4. **Per-role network egress allowlisting** — not implemented. It remains useful defense-in-depth before untrusted repositories/plugins are considered in scope.
5. **MCP permission profiles** — not implemented; finer-grained hardening remains backlog while existing policy/permission controls stay enforced.
6. **Windows Credential Manager integration for NACC-owned secrets** — not implemented. Provider-native credentials remain external and unread; this becomes required if NACC itself begins owning durable secrets.
7. **Usage/Quotas accounting** — no complete runtime/accounting contract has been verified.
8. **Agent Sessions/Terminals management UI** — no complete production contract has been verified.
9. **Custom `nacc-updater` crate** remains non-authoritative/placeholder-level. It is not required for personal local use; if public distribution is reintroduced, release trust should rely on Tauri's updater/signing path rather than reimplementing crypto.

## 8. Local-only acceptance contract

The current target is personal local desktop use, not public production
distribution. Local readiness therefore depends on the machine/repository/data
safety properties that are relevant even for one user:

- privileged execution stays in Rust behind typed IPC with no general webview
  shell/filesystem capability;
- process-tree containment and cancellation/timeout cleanup remain enforced;
- worktree isolation/quarantine and destructive-operation safeguards remain
  enforced;
- provider credentials remain external/unread and persisted evidence is
  redacted/bounded;
- required deterministic quality gates fail closed through the durable
  workflow/retry lifecycle;
- SQLite migrations/persistence preserve durable state;
- unsupported/unverified features stay disabled/unavailable rather than
  pretending to work.

Fresh bounded local evidence from 2026-09-19 is recorded above for these
properties. On that scope, NACC is **LOCAL-READY**.

The following no longer gate local readiness and are retained only for a future
decision to distribute NACC publicly: protected signed release-candidate CI,
Authenticode, clean-machine install testing, updater signature/channel tests,
public packaging/publication evidence, and release-specific provider
certification. Full-workspace CI remains recommended regression evidence, not a
personal-local-use blocker.
